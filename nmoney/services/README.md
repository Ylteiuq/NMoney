# 账本规则和用例

| 文件 | 负责的问题 |
| --- | --- |
| [ledger.py](ledger.py) | 导入时按平台和订单号去重、比较快照时间。处理分类、日常选择、单笔上限、群收款抵扣，以及组织概览查询。 |
| [rules.py](rules.py) | 用 `payment_state` 识别资金性质，用 `evaluate` 算出单笔实付、用途及归属，再用 `summarize` 按分类和月份汇总。 |
| [classification.py](classification.py) | 在指定日期范围运行相似支出初分。用同组交易推断未知用途，并用已有手工用途做留一验证。 |

## 在哪里改统计口径

- **全部支出**按原付款金额 `cents` 累计，包含符合条件的理财买入。**个人实付**对普通付款扣除已知退款和已关联的群收款。全额退款实付为零，部分退款金额未知时实付为 `None`，等金额明确后再累计日常开销。
- 普通付款的**用途**依次看单笔标注、同平台同名商户规则、商品和平台类别推断。仍然未知且没有人工指定时，才采用模型的 `initial_category`。**日常归属**单独取手工选择，其次取初分。改一笔为「非日常」可以保留它的餐饮用途。
- **群收款**在原付款日抵扣。服务先取跨月、跨平台的关联，再筛选本次要展示的原付款。关联回款和批量日常标记使用 `session(immediate=True)`，在核对现有数据前取得写锁。

## 怎样读初分结果

初分复用 [网页的聚类函数](../../web/app.js)。遇到用途未知的付款，至少有两笔其他相似交易提供一致的消费用途才采用推断。证据不足就保留未知。已手工决定或已主动退回待确认的日常选择会保留。留一验证逐笔隐藏目标交易自己的手工标签，用其余手工标签预测，再统计能预测几笔、其中吻合几笔。

从项目根目录执行 `python3 -m nmoney.trial --start 2026-11-01 --end 2026-11-23` 可预览统计。指定 `--db` 可选测试账本，显式加 `--apply` 才写入初分结果。
