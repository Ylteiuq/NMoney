# NMoney 个人账本

想看花销时，把微信和支付宝的明细一起导进来。NMoney 会记住以前的订单和你补过的用途，并按月统计符合条件的消费。

## 启动

在 Mac 上双击同目录的 **启动账本.command**，浏览器会打开账本。使用期间让终端窗口保持打开，结束时在终端按 `Ctrl+C`。也可以在项目目录运行：

```sh
python3 app.py --open
```

需要 Python 3.9 或更高版本。整个项目使用 Python 标准库、SQLite 和原生 HTML/CSS/JavaScript，无需安装依赖。默认地址为 `http://127.0.0.1:8765`，只有这台电脑可以访问。若端口已被其他程序占用，可用 `python3 app.py --open --port 8766`。

## 平时怎么用

1. **导入账单**。从支付平台导出交易明细并解压，选择微信的 `.xlsx` 或支付宝的 `.csv`，点击「导入所选文件」。每个文件都会显示新增、更新和重复笔数。可以隔几周再导，日期可以重叠。
2. **收支概览**。默认显示本月。选择月份或起止日期、支付平台，就能看这个范围的合计和分类分布。可以直接修改单笔上限，点击「应用」后会自动重算并记住设置。
3. **补用途**。点「待分类」进入对应明细，按商户、商品或订单号查找，点「编辑」选分类、写备注。若同平台的某个商户一直是同一种用途，可选「同平台同名商户使用这个分类」。这会应用到既有和未来的同名交易。美团、京东这样的综合平台适合只改这一笔。
4. **复核**。在「交易明细」展开交易对方，可看订单号、原始状态和备注。点「超上限」后选一笔，点「手动计入…」，确认消费用途并保存。重新编辑并取消勾选即可恢复按上限统计。移除商户规则后，其他未手工标注的订单恢复自动分类。

5. **逐笔对账**。点击「查看全部支出」核对原付流水，在每行的日常归属下拉框中选择「计入日常」「非日常」或恢复「待确认」。点击「已确认日常开销」可按用途、时间和实付金额核对图表及逐笔小计。
6. **群收款分摊**。在「群收款分摊」找到朋友的入账，点「关联付款」。候选包含所有日期和平台的支出，优先显示时间最接近的交易。同一笔付款可以关联多人的回款。每笔回款仅抵扣一次，可修改或解除关联。分摊记在原付款日，因此次月到账也会更新上月的实付。分两单买单时，可将回款关联到足以抵扣的主单，另一笔按实付保留。若一笔回款大于每张单，目前不支持拆分关联。
7. **理财买入**。产品明细和按月统计随时间、平台筛选更新。买入金额包含已付款、仍待确认份额的订单。赎回、分红与退款单独保留，不计入买入额。
8. **按分类和商户核账**。点「已计入消费构成」中的任一行进入分类明细。链接保留日期和支付平台，可刷新或用浏览器后退。展开「按商户汇总」可查看当前筛选范围内各商户的笔数和个人实付，点商户名可逐笔核对。
9. **相似支出**。模型在当前日期和平台范围内重新分组。商户名和商品说明转成字符二元组并用 TF‑IDF 加权，对数金额作为辅助特征。模型依次比较交易与各组中心的余弦相似度，低于 0.68 时新建一组。独立列出找不到相似项的付款。你可以展开核对每笔，再确认一组里的待确认项，已有的日常标记会保留。

## 合计怎么算

- **全部支出**汇总平台标为支出的已付款原额，以及平台标为不计收支的有效理财买入。代付、借出、大额、未知用途和后来退款的原单都能逐笔核对。未付款、失败交易、纯账户间提现和收入单独保留。理财卡展示买入明细，金额已包含在全部支出中。
- **已计入消费**包括用途明确、个人实付小于或等于上限的消费，以及手动选择计入的大额消费。个人实付等于原付减已知退款、再减已关联的群收款。默认上限是 **100 元**。例如 100 元可以计入，100.01 元整笔列为「超上限」。金额在数据库中使用整数分。
- **日常开销**汇总初分或手动计入的个人实付。初分沿用餐饮、校园消费、日用和交通四类。咖啡归入餐饮，洗衣归入日用，数码归入休闲，未注明商品的美团单列并保留日常归属待确认。手动选择优先，也可把某笔改回待确认。全额退款实付为零，部分退款金额未知时暂缓累计。
- **待分类**列出上限以内、用途未知的付款。补完用途后自动重新统计。超过上限的未知付款可以在「超上限」里找到。
- **非消费**包括收入、提现、投资、借出、代付待回款、已全额退款等，均保留流水。之后收到的还款或银行卡回款也不会由程序凭金额推断。
- **退款**按原支付单的最新状态处理。全额退款的原支付单不再计入。部分退款在状态中注明金额时按净额统计。缺少退款金额时，原单暂列「退款待核对」。退款入账本身不再冲减合计。若只有退款入账、原单仍显示支付成功，可重导覆盖原付款日期的新明细，让平台状态更新。

## 数据与备份

数据库在 `data/nmoney.sqlite3`，首次启动会自动创建。订单、备注、商户规则、上限例外和群收款关联都在这个文件中。网页通过本机地址处理导入，不会保存上传文件的副本。

日常归属同样保存在数据库。如果升级时旧服务仍在运行，网页会提示并把新标记暂存在当前浏览器。重启后用同一浏览器打开同一账本地址，暂存项会按平台和订单号写入 SQLite，优先保留数据库中已有的人工决定。

备份时先退出程序，再复制 `data/nmoney.sqlite3` 到备份位置。恢复或换机时先退出程序，把备份复制到新项目的同一路径后再次启动。恢复会覆盖目标账本，请先保留原文件。单独复制源码得到的是空账本。

**去重**使用「平台 + 交易订单号」。同一天、同商户、同金额的两笔付款，只要订单号不同，就各算一笔。较新的导出可以更新原始状态。较旧或同批导出跳过。缺少导出时间的文件可以增加新订单，已有订单保留原状。手工备注和分类独立保存。分类优先级为单笔标注、同名商户规则、程序推断。

## 后端结构

一次请求从 `app.application(db_path)` 组装的 WSGI 入口进入。Host 校验通过后，Router 按「方法、路径」匹配一次。API 中间件检查写请求头并读取输入，Controller 从 Request 取参数，调用 Service 后返回 Response。

| 文件 | 职责 |
| --- | --- |
| `app.py` | 加载启动配置，组装 Service、Controller、Router 和中间件，启动本地服务 |
| `nmoney/http.py` | 封装 Request、Response，连接 WSGI 输入流与响应回调 |
| `nmoney/middleware.py` | 校验 Host 和写请求头，将既有的参数与业务错误转换为 HTTP 400 |
| `nmoney/router.py` | 集中注册 8 个 API 和 4 个静态资源，未匹配的方法和路径返回 404 |
| `nmoney/controllers.py` | 提取查询参数、JSON 字段和导入文件，构建 HTTP 响应 |
| `nmoney/services.py` | 处理账本查询、快照去重、单笔标注、上限和群收款分摊 |
| `nmoney/repository.py` | 执行账本的 SQL 查询和写入，返回数据及受影响的行数 |
| `nmoney/infrastructure.py` | 创建连接、启用外键、管理事务和执行建表迁移 |
| `nmoney/statements.py` | 读取微信 Excel 和支付宝 CSV，按列名提取交易并保留完整订单号 |
| `nmoney/rules.py` | 识别资金性质、推断用途、计算上限和月度统计 |
| `nmoney/classification.py` | 运行相似支出初分和留一验证，通过 Repository 保存结果 |
| `nmoney/trial.py`、`nmoney/ledger.py` | 分别提供初分命令行入口和原有的 Python 连接式调用接口 |
| `web/` | 概览、明细和导入页面 |
| `tests/test_http.py`、`tests/test_ledger.py` | 分别验证 HTTP 协议和通过真实应用入口执行的账本业务 |

例如，`POST /api/aa` 由 Controller 取出回款和原付款 ID。Service 在同一事务内核对付款性质、检查累计回款并决定关联或解除，Repository 执行对应 SQL。分摊和批量日常标记沿用 `BEGIN IMMEDIATE`，先取得写锁再读取。用例成功后统一提交，抛出异常时先回滚，再由中间件构建错误响应。

在项目目录执行测试：

```sh
python3 -m unittest discover -s tests -v
node tests/test_clustering.js
```

如需试改规则，用 `python3 app.py --open --port 8766 --db /tmp/nmoney-demo.sqlite3` 启动另一本空账本。

要试分一个日期范围，可运行 `python3 -m nmoney.trial --start 2026-11-01 --end 2026-11-23`。此命令需要本机 Node。默认只预览，加 `--apply` 后保存。已有用途优先；用途未知时，至少两笔相似交易的用途一致才尝试补全。对未说明用途的转账、红包和群收款不据此推测。留一验证会逐笔隐藏手工用途，仅用其余手工用途预测，并分别报告能判断的笔数和吻合的笔数。
